# Morrow example archive

A week of synthetic work (Oct 01–07, 2026) on a fictional Rust library,
in Claude Code, Codex, ChatGPT and claude.ai, plus a Claude-Code-only
parents set, a live set and an annotation session. `FACTS.md` states every
fact the files produce; `expected/` holds the expected results of the
query examples.

The files were generated by the spec repository's
`polylogue-spec/examples/archive/build.py` (spec commit `47d55eeb`). Edit them
here directly; nothing regenerates them.

The `polylogue-testkit` crate lays them out in a temporary home where each
tool writes, converges the engine over it and imports the exports, so
tests read an archive built by the real parsers and writer.

## Differences from the generated files

- Session #6's first user message had the item ID `msg_01a20000u2`, the
  same as #5's first user message with different text. Codex item IDs are
  unique API IDs, and Polylogue treats one ID in two files as one message
  stored once (a fork copies items with their IDs), so the collision hid
  #5's prompt. #6's copy is now `msg_01a20006u2`.

## Counting differences from `FACTS.md`

`FACTS.md` was written before the architecture settled two rules:

- A subagent's session ID is `claude-code:agent-<agentId>`
  (architecture §5.5a), not `<parent>/<agentId>`.
- A Codex rollout is stored one message per item, as items arrive; a model
  request is not grouped into one message up to its `token_count`. The
  example's prompts, tool calls and outcomes are unchanged by this; its
  per-session message counts for #5 and #6 are not comparable.
- Hook spool lines put `event_id`, `event_type` and `observed_at_ms` first,
  as real hook spool files do (the generator wrote `provider`, `session_id` and
  `proc` first, which no real hook spool file does, so collection did not recognize
  them). Every field is kept.

## Cost evidence

Codex token totals in `FACTS.md` are a recorded known subset from independent
usage observations. They do not establish complete request or session costs;
#5 and #6 therefore match `cost:unknown`. The complete-session known total is
5.8626 USD under the example prices, with four sessions' total cost unknown.
The separately priced observation subset is 0.333 USD; its record times do
not establish daily spend. The expected oracle keeps these units separate.
