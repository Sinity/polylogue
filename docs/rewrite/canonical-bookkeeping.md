# Canonical cursor bookkeeping

Claude materialization advances across absent selected-fact slots in its already admitted response cell before returning the next action. Each scan examines at most eight indices and checks cancellation. A supplied null, empty string or empty object remains supplied. Existing value and origin producers retain their field boundary. Skipping to a supplied field checkpoints that chosen cursor before opening a streaming producer.

Codex projection consumes its zero-I/O `AdvanceBlock` transition with the next block step, which still performs at most one provider lookup. Old persisted cursors at that transition remain readable. Actual source, citation, field, value, origin and proof mutations keep their existing durable boundaries and exact Build checks.

This removes bookkeeping checkpoints and worker turns. It does not establish wall-clock dominance, whole-source readiness within a deadline, or actual-corpus acceptance. Read allowances, fairness, cancellation, schema and interpretation recipes are unchanged.

The matched two-contribution synthetic case uses 44 worker actions and 37 committed cursor steps instead of 60 and 53 when selected metadata is absent (16 actions removed, 26.7%). A supplied later null or empty value uses 49 actions and 42 cursor steps instead of 62 and 55 (13 removed, 21.0%). With 64-byte streaming chunks, the same null uses 84 instead of 97 actions; a 1024-character value uses 116 instead of 129. The comparison changes only the old missing-slot cursor advances; all actual field and source work is shared. Cursor sequence excludes value producer mutations, so worker-action totals are reported separately.

Actual small fields still require one worker dispatch and typed installation per field; streamed values require additional producer actions. The bookkeeping reduction does not remove those boundaries or justify a whole-source timing prediction.

Consecutive worker-verified small fields and source ranges use separate typed runs. Every entry retains its ordered cursor and sequence CAS. The writer uses the same single-item transaction helpers for each member, including current source, visibility, phase, active-producer, codec, field and range checks. Entries and cursor changes commit in one transaction; a late member failure rolls back the whole run. Large values, in-flight producers, structural operations and publication keep their existing interfaces.

A worker can also replace consecutive cursor-only `Advance` results without committing each checkpoint. It carries the virtual cursor at the original sequence and folds that progress into the next verified field or citation. Before a streaming producer or structural operation it persists one chosen cursor. Active value/origin producers and their `Verified` cursor checkpoints retain the original single-action path. Cancellation is checked between advances; source read admission ends a seek with durable progress instead of spinning on discarded lookahead. Old persisted cursor shapes remain supported.

Run admission observes the first ordinary action through its existing per-adapter admission. If its aggregate work does not fit, that original action is returned without recomputation. Otherwise all lookahead shares the remaining original allowance for logical parser lookup cells and encoded namespace/key/value bytes, selector visits and requested record bytes, normalized value/descriptor hash work, and retained entries, slot keys, cursors and temporary guard metadata. Repeated selector visits are charged repeatedly. These are logical work and retained-encoding limits. They do not bound physical backing-object verification, frame decompression, allocator usage, RSS, or elapsed time. Existing reader validation and cancellation remain in force; there is no additional query-result or authorization cache.

The eight-extra synthetic case uses 65 flattened single-item actions after absent-slot coalescing. Typed runs alone use 50 actions; cursor coalescing reduces that to 18 (47 fewer than 65, 72.3%). It preserves all eleven fields and eleven citation units. Committed cursor steps fall from 61 to 29 as 32 cursor-only steps are folded; the typed runs additionally combine 15 intermediate steps into their transactions. With an 8192-byte metadata allowance the same output uses 26 actions. With 64-byte streaming chunks it uses 151 actions, retaining producer and verification checkpoints. These counts describe one small synthetic input, not a whole-source throughput or readiness prediction. Source verification/decoding, text/value streaming, structural installation, final evidence computation and publication remain work.
