# Bounded canonical preparation

Claude materialization skips absent selected-fact slots in its already admitted response cell. Each scan examines at most eight indices and checks cancellation. Supplied nulls, empty strings and empty objects remain supplied. Codex projection consumes its zero-I/O `AdvanceBlock` transition with the next block step, which still performs at most one provider lookup. Old persisted cursor shapes remain supported.

Consecutive worker-verified small fields and source ranges use separate typed runs. Every entry retains its ordered cursor and sequence CAS. The writer uses the same single-item transaction helpers for each member, including current source, visibility, phase, active-producer, codec, field and range checks. Entries and cursor changes commit in one transaction; a late member failure rolls back the whole run. Large values, in-flight producers, structural operations and publication keep their existing interfaces.

A worker also coalesces consecutive cursor-only `Advance` results. It carries the virtual cursor at the original sequence and folds progress into the next verified field or citation. Before a streaming producer or structural operation it persists one chosen cursor. Active value/origin producers and their `Verified` checkpoints retain the original single-action path. Cancellation is checked between advances; exhausted admission ends a seek with durable progress.

Run admission observes the first ordinary action through its existing per-adapter admission. If its aggregate work does not fit, that action is returned without recomputation. Otherwise lookahead shares the remaining original allowance for logical parser cells and encoded namespace/key/value bytes, selector visits and requested record bytes, normalized value/descriptor hash work, retained entries, slot keys, cursors and temporary guard metadata. Repeated selector visits are charged repeatedly. These limits do not bound physical backing-object verification, frame decompression, allocator usage, RSS or elapsed time. Existing reader validation and cancellation remain in force; no query-result or authorization cache is added.

The matched eight-extra synthetic case uses 18 worker actions versus 65 flattened single-item actions after absent-slot coalescing, preserving all eleven fields and eleven citation units. Committed cursor steps fall from 61 to 29; typed runs combine another 15 intermediate steps into their transactions. An 8192-byte metadata allowance uses 26 actions; 64-byte streaming chunks use 151. These are small-input work counts, not wall-clock speedups or whole-source readiness claims. Source interpretation recipes, schema and configured allowances remain unchanged.

Directory construction inserts each final node and its edges inside the caller's existing transaction. A node becomes externally visible only when every edge, child lease and root transfer has succeeded and that transaction commits. Failed construction propagates to rollback; no partial ready node is published. This removes a separate building-to-ready UPDATE for each of the sixteen nodes in a replacement path. The three fixed construction write statements reuse compiled SQL on the same connection; each execution still binds its current owner, shape, counts and child references and enforces the same constraints. No query results or authority are cached, and directory read validation and work limits are unchanged.
