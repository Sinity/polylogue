# Query laws shared by both projects

Both query languages were reviewed for composability in October 2026, and each project keeps the laws its review found as executable checks. Some laws hold in both languages and carry the same name. A cross-system query (joint decision 29) relies on those, because an answer that mixes `pl.` and `sx.` rows must not change meaning at the boundary. This file lists them and where each project checks them. Laws that belong to one language stay in that project's spec.

Checks: Sinex `sinex-spec/prototype/query-ref/composition.py` (flake check `sinex-query-ref`); Polylogue `polylogue-spec/prototypes/query-ref/composition.py` (laws 126-133; law 134 is checked by its examples).

## Joint laws

| Law | Statement | Sinex | Polylogue |
|---|---|---|---|
| Filter composition | successive filters equal their conjunction | law 2 | law 126 |
| Three-valued filters | an unknown value satisfies neither a comparison nor its negation | law 2 | law 132 |
| Group closure | a grouped result is a relation: `where`, `sort` and `limit` after `group by` act on the groups | law 3 | law 129 |
| Match order | the order rows are enumerated in never changes which match a join or sequence selects (named "witness order" until 2026-10-12; "witness" keeps the operator's sense, one source's observation) | law 4 | law 130 (`| matches`; the stage and unit were `witnesses` until 2026-10-12) |
| Execution-mode parity | every surface (CLI, RPC, MCP, brief) gives the same answer to the same query, because one server-side assembly answers all of them | law 8 (MCP and the evaluator agree on rows, totals and refusals for every `query.md` §12 example) | law 134 (`plan/testing/laws.md`) |
| Command words | a query whose first unquoted word is a command name is that command, never a full-text search; a first word within two typing mistakes of a unit or command name is refused with a suggestion; quoting searches; a field name is never taken for a search word | law 7 (`query.md` §2) | law 135 (`query.md`, reading the input; `prototypes/query-ref/composition.py`): the same hazard existed (`messges cargo`, `brief yesterday` returned empty searches) and is fixed; near misses of a unit or command within two typing mistakes are refused too, quoting searches |
| The page is not the answer | selecting and ordering exist only in the query text (`limit`, `sort`), so a query's answer is the same on every surface; how many rows travel per response is a request parameter (Polylogue `page_size`, since "page" is its workbench pages; Sinex `page`), with the answer's total count and a cursor, and never changes the answer. Found in both: Polylogue's MCP `limit` was a page size beside the text, and Sinex's MCP tools took `limit` with a default while the clause had none | Polylogue 0eb0643; Sinex `query.md` §11 |
| Closed sets | a value outside a closed-set field's values is refused, naming the set and the unit or field where that value exists; never an empty result. Found in Polylogue (`sessions where outcome:error` matched nothing because `outcome` has three units with different sets) and present in Sinex (`time_quality = captued`, `materials where state = running` returned 0 rows) | Polylogue law 137; Sinex composition law 14 (`query.md` §2) |
| Coarse times | a time carries its precision (`instant`, `second`, `minute`, `day`, `month`, `year`, or `bounded` with an end); a coarse or bounded time takes part in a temporal join only when the join's window is at least as wide as its period (a date cannot establish 60-second proximity), and then as its whole period, the match is marked coarse and ranks after precise matches, and `before`/`after` hold only for the whole period. It applies to `pl.` rows inside Sinex's temporal joins (joint decision 29); Polylogue's own `near:` is semantic ranking, not temporal | law 9 (`model.md` §5, `query.md` §6.1) | `model.md`, Time ("Quality and precision"): every provider time carries Sinex's `time_quality` and `precision`; Polylogue's coarse cases are AI Studio's Drive-time fallback (`file_mtime`, bounded), ZIP entries and Grok CLI (`second`), commit dates (`intrinsic`, `second`); index columns `at_quality`, `at_precision`, `at_until`; published `polylogue.*` events carry both. Polylogue's own `near:` is semantic ranking, so the law applies to `pl.` rows inside Sinex's temporal operators (#29) |

## Each project's own

- **Sinex:** search-result policy (law 1: a fused object and the observations it fuses are one hit, whatever conditions are added). Polylogue has no fused hits. Also `in` ranges and the time buckets (laws 5 and 6).
- **Polylogue:** definition reuse (127), attachment membership (128), ranking separation (131) and defaults bound once (133). Sinex has no saved queries yet, and its search returns no scores to separate. "Defaults bound once" is closest to Sinex's explicit-limits rule (`query.md` §11), but the two are different laws.
