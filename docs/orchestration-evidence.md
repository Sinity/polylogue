# Session orchestration evidence

`Polylogue.get_session_orchestration(session_id)` and `SyncPolylogue.get_session_orchestration(session_id)` return the same versioned `SessionOrchestrationEvidence` model. MCP exposes it through `get(ref="session:<canonical-id>", projection="orchestration")`. Unknown sessions return `None` in Python and the standard `not_found` MCP error. Python callers serialize with `model_dump(mode="json")`.

Version 1 returns `version`, `outcome`, `session_id`, `children`, `topology`, `launches`, `model_segments`, `bead_mentions`, `rate_limits`, `usage`, `coverage`, and `gaps`. It reads the existing archive session, delegation, topology, acquisition and usage owners. It never scans live source paths. Launch prompts and raw artifact filesystem paths are excluded.

Launches distinguish tool requests, stored delegation mappings, and native spawn observations. Requested models stay separate from recorded message models and configured turn models. A recorded dominant child model is labeled as such. Actual execution verification is null; a display name never supplies an identity or model. Children come from stored topology edges. Bead mentions come from explicit Beads tool ID arguments or direct `bd` commands with task ID operands, not dialogue text. They establish mentions, not a task revision, attempt, or completion.

Usage preserves the latest cumulative counter instead of adding repeated snapshots. Counter decreases make the session total unavailable and retain the latest observation for inspection. Stored zero counters cannot distinguish missing wire fields from measured zero, so the response names that gap and reports only positive fields. Message counters are exposed separately as a lower bound. Cumulative usage is never attributed wholesale to the final model or added to child totals. Account quota percentages remain timestamped observations; consumed quota tokens are null.

Coverage separates native event time from acquisition time and the primary raw revision's acquisition/parse watermark. That watermark does not prove current archive freshness. The product currently reads several owner snapshots, so `atomic_snapshot` and `complete` are false and freshness remains an explicit gap. Missing timestamps stay null. Each list is limited to 1,000 observations with truncated sections declared. Topology may include the target's wider rooted family, while `children` includes only direct children and transcript observations exclude inherited messages.

Codex quota windows now survive lowering through a dedicated `rate_limits` session event, and native spawn completion events retain the child thread ID. This is a semantic parser change with no DDL change. The Codex parser and derived replay fingerprint change; historical archives need owner reconvergence before they contain the newly preserved fields. Source code changes alone do not backfill those facts. Existing rows with missing quota windows or spawn identities report gaps, and no reindex or live archive mutation is performed by this read product.
