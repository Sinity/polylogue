# Timeline, logical days and cost

`/timeline` and `/day/YYYY-MM-DD` use the `timeline` command, available on the CLI, MCP and `/api/v1/timeline`. The daemon resolves `day.zone` and `day.logical_start`, including daylight-saving boundaries. The default logical start is 04:00. Change these through the existing setting command; the browser holds no calendar settings.

Activity merges message times, event times and note revision creation times, ordered by time, record kind and opaque ID. Each row names its clock. A session can appear on several days regardless of when it started. The calendar strip and its table count messages, events and note revisions, including revisions later replaced. This day across years selects matching logical month/day records through the chosen date and pages them in chronological order. February 29 uses leap years; the page offers February 28 explicitly. Unknown and unrepresentable times have a separate undated list.

`cost`, also on MCP and `/api/v1/cost`, selects sessions through the same compiler as `measure usage`. Its optional `date` restricts source record times to one logical day. Without it, every response of the selected sessions is included, even outside dates used to select sessions. These are API-equivalent list-price figures, not actual charges or payment dates. The shared usage formatter retains token categories, price catalog, tool-reported amounts, independent observations, unpriced records and unknown response boundaries. Own physical responses are never added to parent-inclusive usage.

By-model rows, daily physical response subtotals and response detail pages use the same session selection and source record period. Daily subtotals additionally select their displayed calendar month, changed by `month`; independent usage observations remain separate in the report. Model controls narrow response details only, leaving the all-model report visible. Unknown models have their own detail link. `undated` selects source records whose time is absent or unrepresentable and cannot be combined with `date`.

Lists default to 50 metadata records with continuation. Bodies open through the shared paged reader. The cursor fixes the query clock and binds the compiled selection, logical-day settings and index generation, so changing any of these starts a new page. The calendar holds one month; older months and earlier recorded years remain reachable. Subscription quota is explicitly archive-wide and remains separate from prices and charges. A usage failure is displayed as Cost unavailable while activity or response details remain visible.

The ignored `day_and_cost_measurements` test retains 30 samples per daemon and authenticated HTTP action in `target/day-cost-measurements.json`, or the path in `POLYLOGUE_DAY_COST_REPORT`. Run it through the AgentCTL `measure` operation with `cargo run --locked --quiet -p xtask -- test -p polylogue --run-ignored only -E 'test(day_and_cost_measurements)'`. Its baseline is the existing usage-query API, not an earlier timeline UI. Browser and restart timings are separate measurements.
