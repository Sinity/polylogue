# Timeline, logical days and cost

The `timeline` command is available on the CLI, MCP and `/api/v1/timeline`. The daemon resolves `day.zone` and `day.logical_start`, including daylight-saving boundaries. The default logical start is 04:00. Change these through the existing setting command; clients hold no calendar settings.

Activity merges message times, event times and note revision creation times, ordered by time, record kind and opaque ID. Each row names its clock. A session can appear on several days regardless of when it started. Calendar counts include messages, events and note revisions, including revisions later replaced. This day across years selects matching logical month/day records through the chosen date and pages them in chronological order. February 29 uses leap years; invalid dates are refused. Unknown and unrepresentable times have a separate undated list. Time indexes bound each source read before date conversion; across-year reads seek one day range per recorded year.

`cost`, also on MCP and `/api/v1/cost`, selects sessions through the same compiler as `measure usage`. Its optional `date` restricts source record times to one logical day. Without it, every response of the selected sessions is included, even outside dates used to select sessions. These are API-equivalent list-price figures, not actual charges or payment dates. The shared usage formatter keeps token categories, price catalog, tool-reported amounts, independent observations, unpriced records and unknown response boundaries. Own physical responses are never added to parent-inclusive usage.

By-model rows, daily physical response subtotals and response detail pages use the same session selection and source record period. Daily subtotals additionally select their displayed calendar month, changed by `month`; independent usage observations remain separate in the report. The `model` option narrows response details only, keeping the all-model report. `unknown_model` selects response details without a recorded model. Dated response pages seek by `(at, id)`; model details filter the response row directly. All-time response pages continue through undated responses after dated ones; an explicit count identifies the unplaceable subset without adding it again to the total. `undated` selects source records whose time is absent or unrepresentable and cannot be combined with `date`.

Lists default to 50 metadata records with continuation. Rows carry record and session IDs for the shared paged reader. The cursor fixes the query clock and binds the compiled selection, logical-day settings and index generation, so changing any of these starts a new page. The calendar holds one month; older months and earlier recorded years remain reachable. Subscription quota is explicitly archive-wide and remains separate from prices and charges. A usage failure is returned separately while activity or response details remain available.

The ignored `day_and_cost_measurements` test records 30 samples per daemon and authenticated HTTP action in `target/day-cost-measurements.json`, or the path in `POLYLOGUE_DAY_COST_REPORT`. Run it through the AgentCTL `measure` operation with `cargo run --locked --quiet -p xtask -- test -p polylogue --run-ignored only -E 'test(day_and_cost_measurements)'`. Its baseline is the existing usage-query API, not an earlier timeline UI. Browser and restart timings are separate measurements.

The ignored `million_message_measurements` Store test compares the reviewed SQL without time indexes to the current Store reads over the same synthetic archive of 1,000,000 messages and 100,000 events across sixteen years. It records five samples per action, setup and index-creation times, query plans and host load in `target/timeline-million.json` (or `POLYLOGUE_TIMELINE_REPORT`). Run it through AgentCTL with `cargo run --locked --quiet -p xtask -- test -p polylogue-store --run-ignored only -E 'test(million_message_measurements)'`.

## Workbench rebuild requirements

The workbench build unit will add `/timeline` and `/day/YYYY-MM-DD` and replace the existing `/cost` page using maud over typed answers and the shared TypeScript shell. This change adds no page routes or per-view scripts.

The timeline pages need a calendar strip with an equivalent table, previous/next day and month navigation, activity links to the shared reader, this day across recorded years, an explicit February 28 alternative on leap day, undated activity and continuation links. The day page needs the shared usage summary and a link to that day's cost details. Use the timeline shell's drag, zoom and superseded-request handling.

The cost page needs session-query and source-record-day controls, all-time and undated selection, by-model and unknown-model response drill-downs, monthly daily response subtotals, response continuation, partial-failure messages and a separately labeled archive-wide quota disclosure. Use the shared `measure usage` formatter for every cost amount, including model and daily figures, and the shared layout and styles.
